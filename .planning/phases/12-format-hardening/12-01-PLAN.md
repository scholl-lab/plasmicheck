  <files>

  <action>
1. **Create `plasmicheck/scripts/format_detection.py`** (new module):
   - `detect_format(file_path: str) -> str` — main entry point returning one of: "snapgene", "xdna", "genbank", "fasta"
   - `read_magic_bytes(file_path: str, n_bytes: int = 16) -> bytes` — read first N bytes
   - `is_snapgene(magic_bytes: bytes) -> bool` — check SnapGene signature: `b'\x09\x00\x00\x00\x0ESnapGene'` (first 13 bytes)
   - `is_xdna(file_path: str) -> bool` — check xDNA: first byte is version (0x00), read 112 bytes, byte 112 (index 111) is 0xFF. Must read full 112 bytes (not just 16).
   - Text-based fallback: try reading as text, check if first line starts with `LOCUS` (genbank) or `>` (fasta). Catch `UnicodeDecodeError` for binary files.
   - On failure: raise `ValueError` with actionable message listing all supported formats: "Unrecognized file format: {filename}. Supported formats: SnapGene (.dna), xDNA (.xdna), GenBank (.gb/.gbk), FASTA (.fasta/.fa). If unsure, export as GenBank from your cloning software (SnapGene, Serial Cloner, Benchling)."
   - Log detected format to stderr via `logging.info(f"Detected format: {format_name}")`.
   - Include proper type annotations, docstrings, `from __future__ import annotations`.

2. **Refactor `plasmicheck/scripts/convert_plasmidfile_to_fasta.py`**:
   - **Remove the local `sanitize_filename` function** (lines 20-22). Import from utils instead: `from .utils import sanitize_filename`. This consolidates the duplication flagged in research.
   - **Add SnapGene support** to `convert_plasmidfile_to_fasta()`: Add `elif file_type == "snapgene":` branch that:
     - Parses with `SeqIO.parse(sanitized_input_file, "snapgene")`
     - Writes to FASTA (sequence only, discard features)
     - Preserves GenBank if requested (convert snapgene -> genbank -> fasta, keeping intermediate .gb)
   - **Override record ID with sanitized filename** for ALL format branches (genbank, xdna, snapgene):
     - After parsing records, set `record.id = sanitize_filename(Path(input_file).stem)` and `record.name = record.id`
     - Set `record.description = f"converted_from={file_type}"` to include provenance
     - This fixes the xDNA `[author` broken ID issue
   - **Wrap BioPython parse calls with actionable error handling**:
     - Catch `Exception` from BioPython, inspect `str(e).lower()` for keywords:
       - "version" -> "Unsupported xDNA version. Export as GenBank (.gb) from SnapGene or Serial Cloner, then use plasmicheck convert."
       - "corrupt" or "truncated" -> "File appears corrupt or truncated. Re-export from your cloning software (SnapGene, Serial Cloner, Benchling)."
       - Other -> "Failed to parse {file}. Supported formats: SnapGene (.dna), xDNA (.xdna), GenBank (.gb/.gbk), FASTA (.fasta/.fa). If unsure, export as GenBank from your cloning software."
     - Re-raise as `ValueError` with `from e` for traceback chain
   - **Update the `file_type` parameter** to accept "snapgene" as valid value (update the ValueError for unsupported types to list snapgene)

3. **Update `plasmicheck/config.json`**:
   - Add `"snapgene": ".dna"` to `supported_formats` section
   - Update `"conversion"` -> `"input_formats"` to include "snapgene": `["genbank", "xdna", "snapgene"]`

4. **Ensure `plasmicheck/scripts/utils.py`** `sanitize_filename` is unchanged (it's the canonical version now).
