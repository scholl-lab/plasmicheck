5. **Index caching with within-run deduplication (CACHE-02)** — In the per-combination loop where `create_indexes(plasmid_fasta, overwrite)` is called (around line 587):

   The cache inherently provides within-run deduplication. Here is the exact flow when the same plasmid appears in multiple combinations (e.g., plasmid P with sequencing files S1, S2, S3):

   **Combination 1 (P x S1):** Cache check for plasmid_fasta -> MISS (first time). Call `create_indexes(plasmid_fasta, overwrite)` to build .mmi and .fai. Then `cache.put_index(plasmid_fasta, plasmid_mmi_path, plasmid_fai_path)` stores both in cache.

   **Combination 2 (P x S2):** Cache check for plasmid_fasta -> HIT (same MD5 as combo 1). Copy cached .mmi to expected `plasmid_index` path via `shutil.copy2`. Copy cached .fai to expected `{plasmid_fasta}.fai` path via `shutil.copy2`. Skip `create_indexes` entirely. Log INFO "Cache HIT".

   **Combination 3 (P x S3):** Same as Combination 2 — cache HIT, copy, skip build.

   This replaces and improves on the `built_indexes` within-run dedup pattern for plasmid indexes. The `built_indexes` set should remain for tracking the human reference index only (which is built once upfront and shared, not per-combination).

   Implementation in the loop body (replace the bare `create_indexes(plasmid_fasta, overwrite)` call around line 587):

   ```python
   # Check cache for plasmid index (provides within-run AND cross-run dedup)
   cached_index = None
   if cache:
       try:
           cached_index = cache.get_index(plasmid_fasta)
       except (OSError, PermissionError) as e:
           logging.warning(f"Cache read error: {e}")

   if cached_index:
       # Cache HIT: restore both .mmi and .fai to expected paths
       shutil.copy2(str(cached_index["mmi"]), plasmid_index)
       fai_target = f"{plasmid_fasta}.fai"
       shutil.copy2(str(cached_index["fai"]), fai_target)
       # No need to call create_indexes — both files now exist
   else:
       # Cache MISS: build indexes normally
       create_indexes(plasmid_fasta, overwrite)
       # Store in cache for future hits (within this run and across runs)
       if cache:
           plasmid_mmi = str(paths.plasmid_index)  # {base}.mmi
           plasmid_fai = f"{plasmid_fasta}.fai"
           try:
               cache.put_index(plasmid_fasta, plasmid_mmi, plasmid_fai)
           except (OSError, PermissionError) as e:
               logging.warning(f"Cache write error: {e}")
   ```

6. **Spliced alignment caching** — In the spliced alignment section (around line 600):
   - Before calling `spliced_alignment()`, check: `if cache and (cached_spliced := cache.get_spliced(plasmid_fasta, human_fasta)):`
   - On cache hit: copy cached files to expected paths using `shutil.copy2`:
     - `cached_spliced["bam"]` -> `spliced_bam`
     - `cached_spliced["fasta"]` -> `spliced_fasta`
     - `cached_spliced["cdna_positions"]` -> `cdna_positions_file`
     Skip `spliced_alignment()`, `extract_human_reference()`, and `extract_plasmid_cdna_positions()` calls. Log at INFO level.
   - After cache hit, still call `create_indexes(spliced_fasta, overwrite)` to build the spliced FASTA index — this is fast and not worth caching separately.
   - On cache miss: run spliced alignment as before, then store results:
     ```python
     if cache:
         try:
             cache.put_spliced(plasmid_fasta, human_fasta, spliced_bam, spliced_fasta, cdna_positions_file)
         except (OSError, PermissionError) as e:
             logging.warning(f"Cache write error: {e}")
     ```

7. **Graceful degradation** — All cache.get/put calls are wrapped in try/except (OSError, PermissionError) as shown above. On failure, log warning and continue without cache. Cache errors must NEVER stop the pipeline.

Keep the existing `built_indexes` set for tracking human index (backward compatibility, still useful for the upfront human index build). The cache adds cross-run persistence on top of within-run dedup for plasmid indexes.
