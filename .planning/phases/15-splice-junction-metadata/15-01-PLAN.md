  **Extraction logic (add within the existing BAM iteration):**
  The function currently iterates all reads. Change it to:
  1. Track junction metadata from the **primary alignment only** -- for each read, check `read.is_secondary or read.is_supplementary` and skip those for junction counting (but still process them for cDNA position extraction as before).
  2. For the primary alignment (first non-secondary, non-supplementary, non-unmapped read):
     - Count N operations (op code 3) in `read.cigartuples` -> `junction_count`
     - `exon_count = junction_count + 1`
     - Collect M operation lengths (op code 0) in order -> `exon_lengths: list[int]`
     - Collect N operation lengths (op code 3) in order -> `intron_lengths: list[int]`
     - `strand = "-" if read.is_reverse else "+"`
     - `chromosome = read.reference_name`
     - `genomic_start = read.reference_start` (0-based)
     - `genomic_end = read.reference_end` (exclusive)
  3. Guard against `read.cigartuples is None` (unmapped reads).
  4. Keep the existing cDNA start/end logic unchanged -- it uses ALL alignments to find the broadest insert region, which is correct.

  **Writing logic (extend the file write at end of function):**
  After the existing 3 lines (cDNA start, cDNA end, INSERT_REGION), append:
  ```
  SpliceJunctionCount: <count or NA>
  ExonCount: <count or NA>
  ExonLengths: <comma-separated or NA>
  IntronLengths: <comma-separated or NA>
  Strand: <+ or - or NA>
  Chromosome: <chr or NA>
  GenomicStart: <pos or NA>
  GenomicEnd: <pos or NA>
  ```
  Use "NA" when no primary alignment was found (junction_count is None).
  Use `','.join(map(str, lengths))` for comma-separated lists, or "NA" if empty.
  For `junction_count == 0` (single-exon gene), write "0" not "NA".

  **Error handling:** If the function currently raises ValueError when no alignment found, change it to write an all-NA cDNA_positions.txt instead of raising. Log a warning. This ensures downstream consumers always have a file to parse. Keep the existing behavior of writing valid start/end when alignments exist.

  **A) Create InsertRegionData dataclass** in compare_alignments.py (before parse_insert_region):

  ```python
  from dataclasses import dataclass

  @dataclass
  class InsertRegionData:
      """Parsed cDNA position and junction metadata."""
      start: int
      end: int
      junction_count: int | None = None
      exon_count: int | None = None
      exon_lengths: list[int] | None = None
      intron_lengths: list[int] | None = None
      strand: str | None = None
      chromosome: str | None = None
      genomic_start: int | None = None
      genomic_end: int | None = None

      def __iter__(self):
          """Support tuple unpacking: start, end = parse_insert_region(file)"""
          return iter((self.start, self.end))
  ```

  The `__iter__` method is CRITICAL for backward compatibility. All existing callers do `insert_region = parse_insert_region(file)` and then use it as a tuple `(start, end)`. The `__iter__` ensures tuple unpacking and tuple-like usage still works.

  **B) Update `parse_insert_region()`** to return `InsertRegionData` instead of `tuple[int, int]`:
  - Keep existing parsing of lines 0-2 (cDNA start, end, INSERT_REGION)
  - Add key-based parsing for new fields (lines 3+). Parse by prefix, not line number, for forward compatibility.
  - Handle old-format files (3 lines only) by defaulting new fields to None.
  - Handle "NA" values: when start/end are "NA", set them to 0 (maintaining current behavior for downstream insert region logic).
  - Update return type annotation to `InsertRegionData`.

  Use helper function inside parse_insert_region:
  ```python
  def _get_field(lines: list[str], prefix: str) -> str | None:
      for line in lines:
          if line.startswith(prefix):
              value = line.split(": ", 1)[1].strip()
              return None if value == "NA" else value
      return None
  ```
